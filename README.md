# Фабрика сайтов-каталогов

Фабрика универсальных магазинов: общая витрина, Cloudflare Worker + D1 + R2, Telegram-бот и мобильная Mini App. JSON создаёт отдельную демонстрацию; после привязки владельца её можно активировать. Основная витрина и корзина переиспользованы из исходного сайта.

Корневой `index.html` — неизменённый исходник на Google Sheets для сохранения рабочей версии. Рабочее приложение использует только `public/` и `src/`, без Sheets, Apps Script, GitHub Pages и VPS.

## Запуск через браузер

[Полная инструкция Cloudflare + GitHub + Telegram](docs/browser-setup.md). Node.js и Терминал на компьютере пользователя не нужны: Workers Builds выполняет `npm run deploy:cloudflare`. Значения задаются в Cloudflare Build variables/secrets; helper применяет D1-миграции и переносит настройки и секреты в runtime.

После деплоя откройте `/platform` и введите PLATFORM_API_KEY. Панель позволяет настроить webhook/команды/меню бота, создать магазин из формы или JSON, выдать приглашение владельцу, активировать и экспортировать каталог. Ключ хранится только в памяти страницы. Владельцы магазинов продолжают управлять ими через Telegram Mini App.

## Шаблоны витрины

В панели `/platform` при создании магазина выберите шаблон и откройте его предпросмотр. Доступны «Универсальный», «Одежда и аксессуары», «Дом и декор» и «Косметика и уход». Три тематических шаблона отличаются типографикой, фоном, карточками и пропорциями изображений; во всех четырёх шаблонах по шесть примерных товаров. Флажок «Добавить примерные товары» можно снять.

Предпросмотры `/templates/fashion`, `/templates/home` и `/templates/beauty` доступны без входа, ничего не записывают в D1 и не принимают заказы. Иллюстрации поставляются вместе с приложением; R2 для них не требуется. Перед активацией замените примерные изображения, описания, цены и остатки реальными данными. Цены в разных валютах заданы отдельно для примера и не являются обменным курсом.

В редакторе → «Настройки» можно сменить шаблон существующей витрины. Товары, заказы, фотографии и цены сохраняются. Цвет и название вариантов настраиваются отдельно. В товарах используются бренд, коллекция, артикул, цвет и до 12 дополнительных характеристик в формате `Название: значение`. Старые поля `team/year/number` читаются как бренд/коллекция/артикул; миграция базы не требуется. Копирование и экспорт сохраняют оформление и характеристики.

API создания принимает `templateId: "fashion" | "home" | "beauty" | "minimal"` и `seedProducts: true | false`; без флажка товары не добавляются. Переданные `products` имеют приоритет над примерами; значения `settings` переопределяют настройки шаблона.

## Управление магазинами в панели фабрики

В `/platform` у каждого магазина есть «Редактировать магазин». В редакторе доступны товары, фотографии, настройки оформления и заказы, включая демо без подключённого владельца. «Все магазины» возвращает к списку. Ключ платформы передаётся редактору только внутри страницы: без URL, localStorage или sessionStorage.

- «Копировать магазин» запрашивает название и slug. Создаётся новое демо без владельца, приглашений и истории заказов. Файлы R2 копируются под новый ID; внешние HTTPS-фото остаются внешними ссылками. Прогресс виден в панели. Большие каталоги копируются небольшими порциями; при закрытой панели работу продолжает cron.
- «Передать магазин» создаёт приглашение для нового Telegram ID. Прежний владелец сохраняет доступ до принятия приглашения. Новый получает каталог и историю заказов, прежний теряет доступ. Ссылка одноразовая, действует 24 часа. Если после выдачи менялись настройки магазина, создайте новое приглашение.
- «Приостановить заказы» сохраняет витрину и существующие заказы, но запрещает новые заказы на сервере. «Возобновить заказы» возвращает приём.
- «Удалить демо» требует ввода slug. Активный магазин или демо с заказами удалить нельзя. Каталог и приглашения удаляются вместе; файлы R2 очищаются с повторными попытками при сбое.

## Локальный запуск

Требуется Node.js 24, npm. Cloudflare-аккаунт для локального D1/R2 не нужен.

```bash
npm ci
cp .dev.vars.example .dev.vars
npm run db:migrate
npm run dev
```

В `.dev.vars` замените ключ платформы на случайную строку минимум 32 символа. Telegram token и webhook secret нужны для работы настоящего бота; интеграционные тесты используют собственные тестовые значения и полностью имитируют Telegram. Никогда не публикуйте `.dev.vars` и `.env`.

В другом терминале установите **такой же** `PLATFORM_API_KEY` в окружение CLI (через секреты shell/менеджер окружения, без записи реальных значений в GitHub). CLI не читает `.dev.vars` автоматически.

```bash
npm run store -- create examples/mira-bags.json
```

Команда вернёт ID магазина и ссылку `http://localhost:8787/demo/mira-bags`. Демо позволяет просмотреть карточки и корзину, но не сохраняет заказы и скрывает контакты продавца. Mini App открывается через Telegram-бота, а не через отдельный логин в браузере.

## Проверка

```bash
npm run check
npm test
npx playwright install chromium
npm run test:browser
npm run build
```

`npm test` использует настоящий локальный Workers runtime, D1 и R2 с имитацией Telegram API. `test:browser` поднимает собственное временное окружение с тестовыми initData, запускает Chromium и проверяет Mini App → витрину → оформление заказа → D1 → статус. Авторизация в рабочем коде не отключается. Browser smoke проверяет 375/390/1280 px, экранирование строк и ошибки сохранения. `build` — dry run, ничего не публикует.

Для своего установленного Chromium можно задать `CHROMIUM_EXECUTABLE`. Для временных скриншотов — `BROWSER_SCREENSHOT_DIR`. Служебные тестовые магазины не попадают в рабочую базу.

Подробные результаты: [docs/verification.md](docs/verification.md).

## Развёртывание Cloudflare и Telegram

1. Авторизуйте Wrangler: `npx wrangler login`.
2. Создайте отдельную БД: `npx wrangler d1 create catalog-factory`. Вставьте её `database_id` в `wrangler.jsonc` вместо нулевого placeholder.
3. Создайте бакет: `npx wrangler r2 bucket create catalog-factory-images`. Не включайте публичный r2.dev: фото выдаёт Worker.
4. Установите `PUBLIC_ORIGIN` (будущий HTTPS-адрес Worker/домена) и `BOT_USERNAME` в `wrangler.jsonc`. Создайте бота в @BotFather.
5. Задайте секреты интерактивно:

```bash
npx wrangler secret put PLATFORM_API_KEY
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
```

6. Проверьте отдельное окружение перед рабочими данными:

```bash
npx wrangler d1 migrations apply catalog-factory --remote
npm run types
npm run check
npm test
npm run build
npx wrangler deploy
```

7. Установите секреты Telegram и `PUBLIC_ORIGIN` в окружение локального setup-скрипта и выполните `npm run telegram:setup`. Он настроит защищённый webhook, команды и кнопку меню. Не вводите секреты в аргументы команд и не публикуйте их в чатах или GitHub.
8. Откройте `/start` в личном чате с ботом. Пока магазина нет, бот покажет Telegram ID. Создайте демо и приглашение на этот ID:

```bash
# STORE_API_ORIGIN в окружении CLI должен указывать на ваш HTTPS Worker.
npm run store -- create examples/mira-bags.json
npm run store -- invite STORE_ID TELEGRAM_USER_ID
```

9. Передайте ссылку приглашения владельцу. Он открывает её в указанном аккаунте Telegram и получает «Управлять магазином». Ссылка действует 24 часа и не позволяет привязаться другому аккаунту.
10. После проверки наполнения и согласия на продажу активируйте:

```bash
npm run store -- activate STORE_ID
```

Ссылка станет `/shop/:slug`; старый `/demo/:slug` перенаправляет на неё. Заказы сохраняются, владелец получает Telegram-уведомление, кнопки меняют реальные статусы. При ошибке Telegram уведомления повторяет cron каждые 10 минут.

Для staging создайте отдельные Worker/БД/бакет/бот и отдельную конфигурацию, не делите продуктивные данные с тестовым окружением. GitHub Actions проверяет код. Cloudflare Workers Builds автоматически публикует коммиты настроенной production branch; merge в `main` не выполняется.

## JSON и импорт таблицы

[examples/mira-bags.json](examples/mira-bags.json) показывает формат. Цены `prices` — целые минимальные единицы: `8500` BYN = `85.00 BYN`. Упрощённые `price`/`currency` поддерживаются для магазина с одной валютой. Варианты: подпись + остаток; пустой/NULL остаток = без ограничения. Новые ID генерируются сервером. Категория создаётся из поля товара.

Одноразовый импорт исходного XLSX (требуется `python -m pip install openpyxl`):

```bash
python scripts/import_xlsx.py path/to/source.xlsx /tmp/store-import.json
npm run store -- create /tmp/store-import.json
```

Исходная таблица не изменяется. Исторические заказы и контакты не импортируются. Для разрешённых фотографий есть `--include-images`; Drive URL преобразуются в ссылки на изображения. Для независимого размещения фото загрузите их в R2 через Mini App.

## Экспорт и передача

```bash
npm run store -- export STORE_ID /tmp/store-export.json
```

Экспорт содержит каталог, настройки, варианты и ссылки на фото. Он не передаёт аккаунт владельца и историю заказов. Для создания нового демо из экспорта сначала перенесите R2-файлы и замените внутренние `/media/...` ссылки на доступные HTTPS-URL либо уберите фото/логотип и загрузите их заново в новом магазине. CLI удаляет старые ID и создаёт новые.

## Структура и границы

- `src/`: API, валидация, Telegram HMAC, каталог, заказы и уведомления.
- `public/`: витрина и Mini App без frontend-фреймворка.
- `migrations/`: схема D1 и атомарные операции с остатками.
- `scripts/`: фабрика JSON, настройка бота, одноразовый XLSX-импорт.
- `tests/`: API/D1/R2 и browser smoke.
- `.github/workflows/ci.yml`: проверки без production deploy.
- [Аудит](docs/audit.md), [архитектура и API](docs/architecture.md), [квоты и стоимость](docs/costs.md).

Пока не реализованы индивидуальные домены, автоматическая передача отдельного Cloudflare-аккаунта, парсер Instagram, автоматические сообщения потенциальным клиентам, онлайн-оплата и CRM. Фотографии и брендинг персонализированных демо используйте с разрешения владельца.

## Оплата услуг через Tribute

Товар https://web.tribute.tg/p/H0x подключён в подготовленном коде: команда `/pay`, учёт покупок и возвратов по Telegram ID. Для запуска нужны API-ключ и настройка webhook. Shop ID для этого товара не требуется. Инструкции и альтернативный режим персональных счетов: [docs/tribute.md](docs/tribute.md).

### Фото заказов, шаблоны и ссылки

В списке и составе заказа показаны фото товаров. Новые заказы сохраняют фото на момент покупки; старые заказы используют доступное фото товара из каталога. Фото берётся на сервере, а не из запроса покупателя.

В `/platform` блок «Фото примеров в шаблонах» позволяет загрузить по одному главному фото на примерный товар или вставить прямую HTTPS-ссылку и сохранить подборку. В карточках товаров также есть поле «Ссылка на фото»; загрузку и ссылки можно сочетать (до 8 фото). Поддерживаются JPEG, PNG и WebP до 3 МБ. Предпросмотр и новые магазины используют эти фото; при создании магазина файлы копируются в его собственную папку. Уже созданные магазины не меняются. Все четыре шаблона содержат по шесть товаров, тематические описания и редактируемые тексты витрины. Контакты продавца и логотип заполняются для конкретного магазина.

«Мой сайт → Скопировать ссылку» и `/myshop` выдают `https://t.me/<bot>?startapp=s_<slug>`. Ссылка открывает публичную витрину через Main App бота; Main App должен указывать на `/admin`. Это ссылка Telegram, а для прямого адреса сайта без персонального поддомена нужен собственный домен. Путь `/s/<slug>` постоянно открывает магазин независимо от перехода из демо в активное состояние; старые `/demo/` и `/shop/` продолжают работать.

Загруженный логотип автоматически используется для favicon и apple-touch-icon витрины. Без логотипа отображается нейтральная иконка Delokay.

### Клиентские домены

В карточке магазина в `/platform` доступно добавление личных доменов, инструкции DNS, проверка DNS/HTTPS и отключение. Первоначальная настройка основной SaaS-зоны и необязательного секрета `CUSTOM_DOMAINS_API_TOKEN` описана в [docs/client-domains.md](docs/client-domains.md). До настройки можно сохранять привязки; реальная активация ожидает подключения Cloudflare for SaaS.

### Язык витрины

При создании демо в `/platform` выберите «Язык сайта»: русский или English. Новые демо получают интерфейс, тематические тексты и примеры товаров на выбранном языке. В существующем магазине язык меняется через редактор → «Ещё» → «Настройки» → «Язык сайта». Переводятся каталог, корзина, доставка, оформление заказа и стандартные сообщения. Собственные названия и описания товаров остаются без изменений; нетронутые тексты шаблона переключаются автоматически. API: `settings.language: "ru" | "en"`, по умолчанию `ru`; предпросмотр: `/templates/fashion?lang=en`. Миграция БД не требуется.

# Импорт персональных демо Instagram

Локальный парсер `Mirrorby/instagram-store-finder`, команда `demos`, использует
штатный API платформы для создания демо, загрузки логотипа/фото в R2 и импорта
подписей публикаций. Ключ платформы остаётся только на Mac.

Товар поддерживает `priceOnRequest: true`: витрина показывает «Цена по запросу» /
«Price on request», фотографии и описание доступны, добавление в корзину отключено.
API заказов также отклоняет такой товар даже после активации магазина.
В редакторе снимите «Цена по запросу» и задайте подтверждённые цены, чтобы продавать
товар. Новые демо по-прежнему создаются без реальных заказов.
