# Клиентские домены

Оператор работает в `/platform`: в карточке магазина раскрывает «Клиентские домены», вводит адрес без протокола и пути, затем нажимает «Подключить / проверить». Панель показывает CNAME, отдельную TXT-запись Delokay и записи подтверждения домена / выпуска HTTPS от Cloudflare. После добавления DNS-записей нужно повторить проверку. Домен активируется только при активных hostname и SSL у Cloudflare, правильной TXT-записи Delokay и успешной HTTPS-проверке реального маршрута.

Каждый адрес (например, `shop.client.com` и `www.client.com`) добавляется отдельно. Корневой домен поддерживается, если DNS-провайдер предоставляет CNAME flattening / ALIAS. При отсутствии такой возможности используйте `www` или поддомен. Простая A-запись на случайный IP Cloudflare не поддерживается. Домен принадлежит одному магазину; максимум пять адресов на магазин.

## Первоначальная настройка оператора

Это выполняется один раз, до первого реального подключения. Покупка домена и включение платных услуг не выполняются приложением автоматически.

1. Подключите отдельный основной домен Delokay к Cloudflare и дождитесь активной зоны. Включите Cloudflare for SaaS / Custom Hostnames.
2. Создайте проксируемую AAAA-запись, например `customers.<ваш-домен> → 100::`. Укажите её как fallback origin в разделе Custom Hostnames и дождитесь Active. Этот origin не использует отдельный сервер: запросы обрабатывает Worker.
3. В этой SaaS-зоне добавьте Workers Route `*/* → catalog-factory`. Правило обрабатывает весь входящий в зону трафик; используйте выделенную зону для этой платформы. Не меняйте DNS других проектов.
4. Создайте Cloudflare API-токен с правами Zone Read, SSL and Certificates Edit и Workers Routes Read только для этой зоны. В `catalog-factory → Settings → Variables and Secrets` сохраните его как **секрет** `CUSTOM_DOMAINS_API_TOKEN`. Не помещайте токен в vars, GitHub, JSON магазина или поля панели.
5. В `/platform → Клиентские домены → Первоначальная настройка Cloudflare` введите Zone ID и CNAME-адрес `customers.<ваш-домен>`. Сохраните и нажмите «Проверить настройку Cloudflare».
6. Подключите один тестовый домен через карточку магазина, добавьте выданные DNS-записи и проверьте реальный HTTPS и оформление заказа.

До выполнения первоначальной настройки можно сохранять привязки доменов, но сайт по ним не активируется. Панель отдельно показывает наличие API-токена и ошибки настройки. Секрет необязателен для обычной работы фабрики.

## Маршрутизация и отключение

На активном клиентском домене `/` открывает привязанный магазин. Разрешены его публичный API, оформление заказа и его фотографии, стили и иллюстрации шаблонов. Панели, webhook и другие магазины на таком домене недоступны. Неизвестный или отключённый домен не открывает чужую витрину. Основная административная поверхность остаётся на `PUBLIC_ORIGIN`.

В конфигурации assets установлен `run_worker_first: true`, чтобы проверка домена выполнялась и для статических файлов. Флаг `global_fetch_strictly_public` позволяет HTTPS-проверке вернуться через публичный маршрут Cloudflare, включая тот же Worker.

Проверка подключения запускается оператором кнопкой; фонового опроса всех доменов нет. При потере ответа на создание сначала ищется уже созданный hostname, что предотвращает повторное создание ресурса. Операции проверки и удаления защищены кратковременной блокировкой. Основную SaaS-зону нельзя заменить, пока есть использующие её подключения или незавершённые операции.

«Отключить домен» сначала запрещает обслуживание домена, затем удаляет подключение Cloudflare и локальную привязку. При ошибке Cloudflare сохраняется отключённая запись с возможностью повторить удаление. Каталог, товары, заказы и стандартная ссылка сохраняются. Демо с привязанным доменом удалить нельзя до отключения адреса. Копирование магазина не переносит домены.

## Проверка

`tests/domains.test.js` проверяет авторизацию, DNS/SSL/HTTPS-проверки, CAS, нормализацию доменов, уникальность привязок, восстановление после потери ответа, отключение и изоляцию витрин. Браузерный сценарий проверяет панель и загрузку витрины с корня отдельного origin. Cloudflare, DNS и выпуск сертификата в автоматических тестах имитируются; реальная проверка возможна после подключения основной зоны и тестового клиентского домена.

Официальные инструкции:
