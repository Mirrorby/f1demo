# Устройство MVP

Один Cloudflare Worker обслуживает все магазины. Static Assets раздают общую витрину и Mini App; `/demo/:slug` и `/shop/:slug` загружают данные соответствующего магазина. Демо после активации перенаправляется на рабочий URL. Фронтенд: обычные HTML/CSS/JS. Backend: TypeScript без runtime-библиотек, ORM и сторонней CRM.

## Данные

- `stores`: slug, статус, Telegram-владелец, настройки JSON, ревизия.
- `products`: данные карточки JSON, ревизия, мягкое удаление.
- `variants`: отдельные варианты и остатки. `NULL` = без ограничения. Вариант задаёт комбинацию размера, цвета или модели одной подписью. Предзаказы не резервируют склад.
- `orders`: неизменяемый снимок покупателя, товаров, цены и суммы. Денежные значения — целые минимальные единицы валюты. Номер уникален в пределах магазина; ID глобально уникален.
- `owner_invites`: хеш одноразового токена, ожидаемый Telegram ID, срок 24 часа.
- `notification_outbox`: долговечная очередь Telegram-уведомлений с lease и повторными попытками.
- `mutation_guards`: транзакционная проверка ревизии при изменении товара и вариантов.

Категории выводятся из товаров и создаются автоматически. Варианты и исторические заказы остаются в базе после удаления товара. Отмена один раз возвращает зарезервированный остаток. Выполненные и отменённые заказы имеют конечный статус.

## Безопасность и согласованность

Mini App передаёт `Authorization: tma <initData>`. Сервер проверяет HMAC по спецификации Telegram, `auth_date` (1 час, допуск будущего времени 30 секунд), дубли параметров и ID подписанного пользователя. Каждый административный endpoint загружает магазин по `id AND owner_id`. Данные браузера `initDataUnsafe` не используются для выдачи прав.

Фабрика доступна только по серверному `PLATFORM_API_KEY`, минимум 32 символа. Его нет в клиентском коде. Webhook защищён отдельным `TELEGRAM_WEBHOOK_SECRET`. Привязка разрешена только в личном чате указанного Telegram ID. Владельца нельзя заменить ссылкой приглашения. Для смены владельца требуется отдельная процедура вне MVP.

Заказ содержит только ID товара/варианта, количество и ожидаемую цену за единицу. Сервер повторно читает актуальный каталог и рассчитывает сумму. SQLite trigger проверяет ревизии и остатки и резервирует товар в одной транзакции с INSERT заказа. Изменение остатков повышает ревизию товара, чтобы старый редактор админки не перезаписал свежие остатки. Настройки и товары используют оптимистические ревизии.

`Idempotency-Key` действует в пределах магазина. Повтор одинакового запроса возвращает тот же заказ; другой запрос с тем же ключом получает 409. Ключ сохраняется в sessionStorage покупателя до подтверждения заказа. Неуспешный запрос не очищает корзину. Ограничение: 10 новых заказов за час с одного IP на магазин (в D1 хранится SHA-256, исходный IP не сохраняется).

Изображения: JPEG/PNG/WebP, до 3 МБ, проверка MIME и сигнатуры файла. SVG запрещён. Mini App уменьшает фото до 1600 пикселей и WebP перед загрузкой. R2-ключ включает store ID и случайный UUID. Нельзя привязать внутреннее фото другого магазина. Фото — публичные ресурсы каталога, а не конфиденциальные документы.

Уведомление отправляется после успешного сохранения заказа. Ошибка Telegram не теряет заказ: cron раз в 10 минут повторяет отправку. Lease предотвращает обычные конкурентные дубли; Telegram не предоставляет idempotency для `sendMessage`, поэтому при сбое после доставки и до отметки `sent_at` повтор уведомления возможен. Заказ в D1 остаётся один.

## API

| Метод      | Путь                                        | Доступ                                   |
| ---------- | ------------------------------------------- | ---------------------------------------- |
| GET        | `/api/stores/:slug`                         | Публичный каталог без данных владельца   |
| POST       | `/api/stores/:slug/orders`                  | Только активный магазин; Idempotency-Key |
| GET        | `/api/admin/stores`                         | Подписанный Telegram-пользователь        |
| GET        | `/api/admin/stores/:id`                     | Владелец; настройки и счётчики           |
| GET/POST   | `/api/admin/stores/:id/products`            | Владелец                                 |
| PUT/DELETE | `/api/admin/stores/:id/products/:productId` | Владелец; ревизия                        |
| GET        | `/api/admin/stores/:id/orders`              | Владелец; status, offset, 50 на страницу |
| GET/PATCH  | `/api/admin/stores/:id/orders/:orderId`     | Владелец                                 |
| PUT        | `/api/admin/stores/:id/settings`            | Владелец; ревизия                        |
| POST       | `/api/admin/stores/:id/images`              | Владелец; бинарное изображение           |
| POST       | `/api/telegram/webhook`                     | Telegram webhook secret                  |
| POST       | `/api/platform/stores`                      | Ключ платформы; создание демо            |
| POST       | `/api/platform/stores/:id/invite`           | Ключ платформы; ожидаемый Telegram ID    |
| POST       | `/api/platform/stores/:id/activate`         | Ключ платформы; владелец уже подключён   |
| GET        | `/api/platform/stores/:id/export`           | Ключ платформы; JSON каталога и настроек |

## Границы версии

200 товаров при создании JSON, 500 товаров в магазине, 30 вариантов, 8 фото на товар, 20 позиций и до 99 единиц на позицию в заказе. Каталог загружается целиком; перед большими каталогами нужны пагинация и замеры CPU. Эти ограничения валидируются сервером.

Экспорт JSON включает каталог, настройки и ссылки на фото, без владельца и заказов. Перенос самих R2-файлов и подключение индивидуальных доменов требуют отдельной процедуры. Общий движок и схема не препятствуют отдельному окружению. Парсинг Instagram, массовые сообщения, CRM и онлайн-оплата не входят в MVP.

R2 сейчас хранит также фото, которые владелец загрузил, но не сохранил в карточку. Автоматическое удаление таких объектов не включено: до масштабирования нужен инструмент сверки ссылок и очистки с периодом ожидания. Контролируйте объём бакета.
