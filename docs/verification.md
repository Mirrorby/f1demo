# Проверка MVP

Проверено локально 12 октября 2026. Использован настоящий Cloudflare Workers runtime (Miniflare/workerd), D1/SQLite, R2 и Chromium. Telegram Bot API имитировался; реальные токены и сообщения пользователям не использовались.

## Сценарий браузера

Владелец открывает Mini App → добавляет товар без размеров и меняет название магазина → витрина загружает обновлённые данные → покупатель добавляет товар и заполняет доставку → API сохраняет заказ → Mini App показывает заказ и меняет его статус в D1.

| Граница                   | Результат | Проверка                                                                                                      |
| ------------------------- | --------- | ------------------------------------------------------------------------------------------------------------- |
| Mini App → авторизация    | Пройдено  | Тестовые initData подписаны тем же алгоритмом; рабочий сервер проверяет подпись                               |
| Форма товара → API → D1   | Пройдено  | Новая карточка с ценой 15,50 BYN появляется через публичный API                                               |
| Настройки → витрина       | Пройдено  | Новый заголовок магазина отображается без деплоя                                                              |
| Корзина → API → заказ     | Пройдено  | Подтверждение с серверным номером; одна строка заказа в D1                                                    |
| Ошибка API → UI           | Пройдено  | При 503 корзина сохраняется; окно подтверждения не открывается                                                |
| Заказ → Mini App → статус | Пройдено  | Кнопка «Принять» сохраняет processing и обновляет интерфейс                                                   |
| Демонстрация              | Пройдено  | Баннер демо; контакты скрыты; сервер отвергает checkout                                                       |
| XSS и мобильная ширина    | Пройдено  | HTML-подобные названия/категории отображаются текстом; нет горизонтального переполнения на 375, 390 и 1280 px |

## Интеграционные сценарии

`npm test`: 17 сценариев пройдено, 0 ошибок. Проверяет:

1. Раздельные каталоги и asset routing, 404 неизвестного магазина.
2. Валидные, поддельные, старые, будущие и повторяющиеся параметры initData.
3. Недоступность товаров, заказов, настроек и uploads другого владельца.
4. Запрет заказов демо, чужих товаров, устаревшей цены и неверного количества.
5. Серверный расчёт скидки, резервирование и уведомление нужного владельца.
6. Повторные и одновременные запросы с одним Idempotency-Key.
7. Конкурентную продажу последней единицы и rollback неуспешного INSERT.
8. Отмену, однократное возвращение остатка и конечные статусы.
9. Создание, редактирование, ревизии и мягкое удаление товаров; обновление настроек.
10. Фактическую сигнатуру фото и запрет привязки R2-объекта другого магазина.
11. Webhook secret, ожидаемый Telegram ID и одноразовое приглашение; активацию.
12. Права владельца и реальное сохранение статуса через callback бота.
13. Валидацию JSON, slug collisions и экспорт данных.
14. Сохранение заказа при ошибке Telegram и повторную доставку через scheduled handler.
15. Лимит размера upload и запрет чужих variant IDs.
16. Лимит checkout-запросов.
17. Защиту на уровне БД от конфликтов при переключении валют и изменении цен.

Также пройдены TypeScript, синтаксис JS, форматирование, локальная миграция, `wrangler deploy --dry-run`, одноразовый импорт четырёх товаров XLSX. Исходный `index.html` сохранён без изменений.

## Не проверено в реальном аккаунте

Облачный deploy, публичный HTTPS, настоящее initData из Telegram-клиента, webhook delivery Telegram, ограничения CPU Free в Cloudflare и фактический bill. Браузер использовал имитацию Telegram SDK только в тестовом окружении, рабочая Mini App загружает официальный SDK.

Обычный `wrangler dev` в контейнере этого сеанса встретил ограничение ОС (`uv_interface_addresses`); browser smoke запускал тот же Worker, D1 и R2 через локальный HTTP-сервер Miniflare. На компьютере пользователя следует дополнительно проверить стандартный `npm run dev`.

Для production-пилота: создать отдельные D1/R2, установить PUBLIC_ORIGIN/BOT_USERNAME и три секрета, настроить webhook, подключить владельца, проверить заказ с телефона и его получение в реальном Telegram, затем активировать рабочий магазин. До этого облачный MVP нельзя считать запущенным.
