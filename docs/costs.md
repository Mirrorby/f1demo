# Бесплатные лимиты и контроль затрат

Проверено 12 октября 2026 по официальным страницам, ссылки ниже. Квоты общие для аккаунта, а не новые на каждый магазин.

| Ресурс         | Включено бесплатно                                                           | Что учитывать в этом проекте                                                                                 |
| -------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Workers        | 100 000 вызовов в день; 10 мс CPU на HTTP-вызов                              | HTML маршруты, API, Mini App, webhook и раздача R2-фото вызывают Worker                                      |
| Static Assets  | Бесплатные неограниченные запросы                                            | CSS/JS и статические страницы обходят Worker, если не совпадают с run_worker_first                           |
| D1             | 5 млн прочитанных строк/день; 100 000 записанных строк/день; 5 ГБ на аккаунт | На Free одна БД ограничена 500 МБ; до 10 БД; 50 запросов к D1 на вызов Worker                                |
| R2 Standard    | 10 ГБ-месяц; 1 млн операций A/месяц; 10 млн B/месяц                          | За превышение начисляется плата; Infrequent Access не покрывается этим free tier; egress бесплатный          |
| GitHub Actions | Standard hosted runners бесплатны для публичного репозитория                 | Workflow использует Ubuntu и запускается на push/PR. Для приватного репозитория действуют квоты вашего плана |

Источники: [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [Static Assets billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [R2 pricing](https://developers.cloudflare.com/r2/pricing/), [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

В базе есть индексы по магазину, владельцу, товарам, заказам, очереди и IP/времени. Каталог не опрашивается каждую минуту: он загружается при открытии витрины. Настройки и остатки не кэшируются с риском устаревания. Заказы валидируются по текущим данным.

Создание магазина выполняет 3 D1 statements через JSON table inserts. Редактирование товара с 30 вариантами укладывается в 50 statements. Cron обрабатывает максимум 10 уведомлений, чтобы не выходить за лимит запросов D1. При больших очередях время доставки уведомлений увеличится; заказы сразу доступны в панели. HTTP-вызов успешного checkout запускает доставку своего уведомления немедленно.

Пример оценки, не измерение нагрузки: 100 товаров × 3 фото × 250 КБ ≈ 75 МБ на магазин. 100 таких магазинов ≈ 7,5 ГБ до логотипов и неиспользуемых загрузок. Если по 100 посещений в день и каждое фото действительно запрошено, по 10 фото/посещение, получится около 100 000 вызовов фото в день — это уже почти вся квота Worker без API и HTML. Ленивые загрузки и browser cache уменьшают запросы, но нельзя обещать безлимитную бесплатную работу.

Каталог из 100 товаров и одного варианта на товар требует примерно 1 строки магазина + 100 товаров + 100 вариантов на полное чтение; фактические rows_read зависят от плана SQLite. Фото в R2 не расходуют строки D1. Максимальные 500 товаров в каталоге и 200 при импорте не являются доказательством укладывания в 10 мс CPU: перед большим импортом/нагрузкой нужны замеры Cloudflare CPU p95/p99 и rows_read/rows_written.

Контроль перед масштабированием:

1. Dashboard Workers: количество запросов, CPU, ошибки лимитов.
2. D1 Metrics: прочитанные/записанные строки, размер БД.
3. R2: занятое место, операции A/B, неиспользуемые объекты.
4. Billing: уведомления о расходах. R2 free tier не является автоматическим жёстким стопом расходов.

Worker и R2 здесь не развёрнуты в аккаунте, поэтому фактическая облачная стоимость и CPU не измерены. Платные API и VPS приложению не нужны. Собственный домен и расходы выше бесплатных квот оплачиваются отдельно.
